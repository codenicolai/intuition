# CLAUDE.md

Context and rules for AI assistants working in this repository.

## Project

Intuition UI: agnostic, AI-first component library built on Web Components. Undergraduate thesis (UTFPR). Each component is defined once by a base signature (Custom Elements Manifest); framework ports (React, Vue, Svelte) and AI documentation (`llms.txt`) derive from it.

Research question: can generative AI interface components be reused across web frameworks with low integration effort?

## Stack (see `docs/adr/`)

- TypeScript 7 (`experimentalDecorators: true`, `useDefineForClassFields: false`)
- Lit 3 for components
- npm workspaces, packages in `packages/*`: `core`, `react`, `vue`, `svelte`
- Build: `tsc` to ESM (no bundler) + `esbuild` single-file CDN bundle
- Dev server: `@web/dev-server`; tests: `@web/test-runner` + Playwright (Chromium), `@open-wc/testing`, tests in `packages/*/test/`
- Components: Shadow DOM, minimal styles with `--iu-*` CSS custom properties and `::part()`, form-associated when relevant, JSDoc tags for the manifest (ADR 0012)
- Visual baseline similar to shadcn/ui (neutral palette, 14px text, 36px default height, 8px radius); system font by default; Enter submits forms through a hidden native submit button
- Test apps outside the repo: `~/Documents/vue-intuition`, `~/Documents/react-intuition`, `~/Documents/portfolio` (route `/intuition`, SvelteKit)
- Lint/format: Biome (single quotes, 2 spaces)
- Node 22+
- Tag prefix: `iu-` (e.g. `<iu-button>`)
- Custom events: kebab-case with `iu-` prefix (`iu-send`), `detail` payload, bubbles + composed; reuse native events when possible. Hyphenated names work in React 19, Vue 3 and Svelte 5 (tested in `e2e/tests/events.spec.ts`)
- Base signature: `packages/core/custom-elements.json` (Custom Elements Manifest), generated by `npm run analyze -w @intuition-ui/core` (also part of `build`) and committed. `npm run lint` fails if it is out of date. Property types are written as inline literal unions so the manifest lists the accepted values; mark non-public members `private` or `@internal`
- Ports: `packages/react` (`<Button>`), `packages/vue` (`IuButton`, used as `<iu-button>` in kebab-case; never combine with `isCustomElement` for `iu-*`), `packages/svelte` (`<Button>`), each generated from the manifest by its `scripts/generate.mjs` (`npm run generate -w <package>`, also part of `build`). Generated files (`*.generated.ts`, `src/generated/`) are committed and checked by `npm run lint`. Never edit them by hand; change the core or the generator
- Integration suite: `e2e/` (isolated package; React, Vue, Svelte apps + Playwright). Run with `cd e2e && npm install && npm test` after building the library
- Package scope: `@intuition-ui`
- License: MIT
- Code, comments, README and docs in English

## Working rules

- Small steps.
- Architecture decisions belong to the author: present options, recommend one, wait for the answer.
- One ADR per major decision in `docs/adr/` (architecture, public API, tooling, process); small adjustments and fixes need no record beyond the commit. Use the template in `docs/adr/template.md`. Revised ADRs are never deleted; mark them "Superseded by ADR NNNN".
- Every major change (new component, API or signature change, behavior or visual change, new port, build change) runs the integration suite in React, Vue and Svelte and saves dated snapshots to `snapshots/` (ADR 0014).
- Conventional Commits. Never commit without the author's confirmation.
- Avoid em dashes in documentation.
- Cite sources with links; state clearly when something is an inference.
- Stay within the approved scope (no iterative AI correction loop, no native non-webview UIs).
